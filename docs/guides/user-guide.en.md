# Zhilan quick guide

The default language is Simplified Chinese. Choose English at the top of any full-settings page or in the first section of sidebar quick settings. Pages, the save context menu, address-bar search hints and toolbar status update together without clearing drafts or active tasks. Bookmark names, personal rules and model-generated content stay unchanged. Extension metadata and shortcut descriptions in the browser extension manager follow the browser language.


## Recently saved bookmarks

Choose **Recently saved** in the single row of **Folders / Recently saved / History** to browse newest first. Filter by today, the last 7/30/90/360 days or all time, then type keywords. The automatic recent view starts at 90 days. Bookmarks without a recorded save date appear only in All time. Dates come from the browser; importing or recreating bookmarks may change them.

For example, enter “a drawing tool I recently bookmarked” and click **Find with AI**. Zhilan first filters native save dates locally to the last 90 days, then assesses allowed bookmarks in batches, prioritizing relevant folders and local matches. Ordinary queries pause after initial matches; choose **Search remaining bookmarks** to continue, or explicitly ask for all matches to scan continuously. Only after that phase completes with no confirmed match does it check days 91–360, without resending already checked bookmarks or automatically widening further. Common explicit dates such as “last week” or “the past month” use that period; manual filters intersect explicit query dates and never expand automatically. Failure or cancellation does not trigger expansion; confirmed and uncertain results remain. Ordinary AI queries without a recent-collection condition or recent view keep all permitted bookmarks in scope, with unexamined items available through continuation.

## Find previously visited pages

Choose **History** below the search box, then explicitly enable history access. Use the same row of **Folders**, **Recently saved** and **History** to switch views. Browse recent visits or search titles, URLs, domains and Chinese pinyin. Choose 7 days, 30 days, custom dates or all available history. **Read more history** appears when a retrieval batch reaches its limit; “All available history” selects the date range, not a guarantee that every record has already loaded.

For a description such as “the flowchart tool I visited last week”, click **AI history search**. This uses your assigned search model: query interpretation followed by comparison of at most 80 candidates within the selected date range. Results reference real visits, without page bodies; semantically relevant pages can still be missed during retrieval. Each row shows a website icon and page name. Click to open, or right-click / use the row menu to open in another window, copy or bookmark. Visit time and bookmark status appear in the tooltip and menu. Bookmarking uses the existing folder choice, optional AI suggestion and final confirmation, without automatic saving.

Ordinary history search stays local, with no persistent history database. Browser deletion or permission revocation clears the search cache and invalidates pending AI results. Choose **Turn off history access** in the menu beside the date range to revoke permission without deleting browser history. An explicitly opened bookmark draft remains available until cancelled or saved. The `zl` address-bar shortcut continues to search bookmarks only.

## Bookmark check (no AI required)

Choose **Bookmark check** below the sidebar search box, or **Bookmark check** in full settings. Select all bookmarks or a folder, then choose **Check now** under **Broken links**. **Duplicates** lists exact and possible matches locally.

The first link check requests website access. Checks read response status without reading page text. The default **Site unreachable** list requires a failed page connection and repeated failed checks of the website entry over HTTP and HTTPS. **Page issues** are separate, with filters for **Page not found**, **Login or access restrictions**, **Redirects** and **Temporary errors**. Any HTTP response, including 404, 403 or 503, proves a server answered and cannot establish that a whole website disappeared. Temporary network conditions can still affect checks; permanent closure or migration cannot be confirmed automatically. Old connection failures need a new website check. Open either the bookmarked page or website home to verify. Background requests can differ from signed-in browser navigation. Choose **Works for me** for a link you can open to skip future weekly checks; choose **Resume checking** under **All results** to clear that confirmation. Open the original page to verify it before selecting deletion. Duplicate groups require an explicit item to keep. Deletions need confirmation and support previewed undo under **Export and backup → Backups and recovery records**; follow recovery guidance for identity or identical-URL conflicts. Checking itself never deletes or moves bookmarks.

Enable **Check weekly** to check the selected scope every seven days. Checks cannot run while the browser is closed; missed checks run after reopening. Progress is saved in the background, supports pause/resume and survives closing settings. Deliberately paused work needs manual resume. Reports stay local and are replaced by the next full check; edited or deleted bookmarks do not inherit old verdicts. A scan supports up to 50,000 bookmarks; choose smaller folders for larger collections.

For a deleted or changed bookmark in save confirmation, **Remove from list** clears the reminder. **Review later** keeps it pending.

## Bookmarks and other features

Zhilan works with native Chrome / Edge bookmarks. No Zhilan account is required. Start with local browsing and search; AI is optional.

**Search folder** defaults to **All folders**. Choosing a folder limits local search, Recently saved and AI search to that folder and its descendants, together with the **Date saved** filter. Continuation and automatic checks of older saves retain that folder scope. Changing folders ends the current AI search and clears continuation; click **Find with AI** again to start a new search. The selection stays in the current page only. If the selected folder is deleted, choose another folder. History search is independent.

1. **Install:** follow [installation](install.md), build the source and load `extension/dist` unpacked. Pin the toolbar icon. A click opens the overlay sidebar; Appearance can switch to the browser side panel. Settings opens the full workspace. The directory remembers expanded folders and your last reading position across reopening, settings/search and browser restarts. If the original bookmark is gone, it returns to an available folder or nearby position. Position stays local and never opens a page automatically.
2. **Find bookmarks:** search by title, URL, folder, Chinese pinyin or initials locally. Click a result to open it. Use the context menu or actions button to edit, move, copy or delete. Deletion asks only “Confirm deletion?” with cancel/confirm buttons. Successful actions update the list without leaving a completion message at the top; failures and unknown outcomes still show a message. `Alt+Shift+K` opens search; `Ctrl+K` / `⌘K` focuses search inside Zhilan. In the address bar type `zl`, Tab/Space, then a query.
3. **Connect AI:** in **AI services**, add an existing provider, enter the endpoint/key, fetch and explicitly select a model, then assign models to features. Provider charges apply. Remembered keys are stored in plaintext in extension-local storage; the add-connection form currently selects remember by default. Temporary keys are page-scoped and are generally unavailable to background native-save classification. Saving completes setup. You can check the connection with synthetic content in service settings. After installation, the sidebar shows steps for AI setup, bookmarking, search and organization. Dismiss them when ready; reopen them from Getting started in sidebar settings.
4. **Save:** use the browser star or `Ctrl+D`. Once background classification and name advice finish, a confirmation popup opens automatically at the extension icon in the top-right of the browser window (the extension's toolbar popup, Chrome/Edge 127+). It never opens a window, tab or taskbar entry. The popup is prefilled with the AI name and folder; choose another destination in an expandable folder tree that opens at the current folder, and confirm the name and folder together. Details stay collapsed until you open them, and collapsing details or the folder tree shrinks the popup. You can confirm after leaving it idle without losing your edits; changes made to the bookmark or folder elsewhere prompt another review. Consecutive saves share one popup and queue (shown as 1/N); later results never replace what you are editing. If clicking the page closes the popup, the extension icon or the sidebar's **bookmarks to review** entry reopens it with your draft intact. Confirming unchanged values performs no bookmark write. Closing or **Review later** keeps the bookmark and its classification. While the window is in the background, in fullscreen, or the browser's own bookmark bubble is still open, the popup waits instead of taking focus; if it still cannot appear after about a minute, the extension icon shows a hint and opens it on click. The extension's own save shortcut and page context menu save the current page in the same popup. Local-rule saves also wait for name advice. Imports and bursts of new bookmarks (such as sync) do not open the popup; browser events do not identify user actions versus synchronization, so a single synced bookmark can still open it. Undo classification from the popup's details or Save history; permanent website rules require separate explicit confirmation.
5. **AI search:** explicitly click **Find with AI**. For more than 100 in-scope bookmarks across multiple folders, AI first prioritizes folders using their paths, counts and a few title samples. It then assesses batches of up to 100, combining folder order with cross-folder local hits. Ordinary queries pause after initial matches; **Search remaining bookmarks** checks the remainder without repeating completed batches. Queries explicitly asking for all/every match scan continuously. Folder-planning failures fall back to local order. No-match searches continue, and unexamined items remain pending rather than being marked irrelevant. The interface keeps actions, coverage counts, results and necessary error messages, without helper paragraphs or repeated completion notices. Uncertain items remain expandable. Cancellation or failure retains completed results. Full scans still cost more time and tokens. Models see titles, URLs and folder paths, not page bodies; checking every item does not guarantee perfect semantic judgment. Clear whole-query website requests such as `all bookmarks from zhihu.com` or `site:zhihu.com` run locally, including question/answer and article pages. `folder:"Study"` matches a uniquely named folder and its descendants. Extra topics, exclusions or ambiguous folder names use the AI search workflow above. Privacy-excluded bookmarks remain locally searchable and are never sent; local-only matches are shown separately during semantic searches. Bookmark changes mark coverage incomplete and require a new search.
6. **Organize:** select a scope and settings. All permitted bookmark titles, URLs and original paths are analyzed in batches before topics are combined into a category draft, including when the scope has no subfolders. Every bookmark is then assigned or explicitly marked keep/uncertain. Before human review, missing categories can trigger one draft revision followed by a fresh assignment of every bookmark. Review the complete tree, proposed changes and uncertain items before confirming execution; omitted answers are rejected rather than treated as keep. Uncertain items have no individual move suggestion, but selected folder changes can still affect their paths. No native bookmarks change during generation.

   “Unfiled only” includes bookmarks directly inside the selected folder. It can create categories without moving, renaming or cleaning up existing subfolders. Scope, style, hierarchy and protected folders remain constraints. Analysis and assignment both use model requests; revision adds requests and Token usage. Generation continues in the background, with completed analysis saved for explicit continuation after interruption. Older saved tasks retain their original folder-confirmation workflow. Review duplicate groups and original URLs before confirming deletion.
7. **Import/export:** import HTML, JSON, CSV, TXT or Markdown and review before applying. Export selected bookmarks as HTML, JSON or Markdown. Exports contain original URLs, exclude keys/settings/rules/logs and are not complete recovery backups. Optional automatic JSON output overwrites a dedicated authorized file while the browser is running.
8. **Recover:** open Export & backup, expand backup/recovery records, preview undo and confirm. For unknown outcomes, reconcile current state without replaying. Do not clear storage or uninstall to hide an unresolved operation; see [recovery](recovery.md).

Review **Privacy & rules** before enabling AI. Exclude private folders, optionally strip query/fragment from AI URLs, and keep page-body assistance off unless needed. AI exclusions do not change export scope. See the [privacy policy](../privacy.en.md).

## Personal preferences and progressive review

Completed classifications appear while organization continues, with **Uncertain bookmarks** in a separate section. Select one or several bookmarks (up to 100 per action), choose a destination and confirm, or submit feedback to reclassify only that selection. Feedback runs after the current batch; newer manual confirmations take precedence over pending AI replies. Saved review and feedback survive interruption and explicit resume.

Content analysis extracts topics from titles, URLs and original paths, without page bodies. Classification assigns each bookmark a destination, keep decision or uncertainty. Before human review begins, missing categories may trigger one taxonomy revision, clearly labeled as round two. Content analysis is retained and there is no automatic third pass. Once you confirm or submit feedback, the current taxonomy stays fixed. Native bookmarks change only after review of the full plan and final confirmation.

The dedicated **Personal preferences** menu shows remembered content, or “None yet” when empty. Zhilan records manual folder changes, edits to AI-proposed bookmark names, and organizer destination selections, explicit classification approvals and reclassification feedback. Native Chrome/Edge bookmark-manager moves and renames are also recorded. Browser events do not identify their source, so equivalent changes from sync or other extensions may also be recorded. Zhilan suppresses its own classification, organization and recovery writes and reorder-only events. Unchanged adoption of an AI name is not a correction; explicit organizer classification approval is remembered.

Preference text is limited to **3000 Unicode characters and 10 entries** in total, including newlines between entries. Raw actions stay in the local learning queue. The organize model summarizes supported classification criteria or naming habits; only a successful summary becomes a preference and merges with the usable profile, removing duplication and giving newer choices priority. For example, explicit feedback to file API tutorials under Learning rather than Tools supports treating those tutorials as learning references, rather than repeating the move. A single choice supports only a narrow interpretation; unclear reasons must not become invented purposes or private motives. Edit, disable, delete or add content in settings; oversized manual additions or edits also trigger whole-profile compression. Failure retains the existing profile and never rolls back bookmarks; failed input remains in local job records without automatic retry. Oversized legacy records retain a local migration copy; only enabled, valid content participates in updates.

Subsequent bookmark search, organize, rename, save and import-classification requests use applicable enabled preferences, with current instructions taking priority. Organizer review records intent; native bookmarks move only after final confirmation. Stale or privacy-excluded evidence, disabled entries and pending rules are withheld. History and synthetic connection tests do not use preferences. Changes affect subsequent requests and cannot recall previously sent data.
