# 目录规则 / Repository layout

| 路径 / Path | 用途 / Purpose | Git |
| --- | --- | --- |
| `extension/` | 生产代码、构建配置、单元/集成/浏览器测试 / production source, build configuration and tests | Yes |
| `docs/guides/` | 安装、使用、模型与恢复 / installation, usage, models and recovery | Yes |
| `docs/reference/` | 数据格式和模型协议 / data formats and model protocols | Yes |
| `docs/development/` | 架构、目录约定、评测 / architecture, layout and evaluation | Yes |
| `docs/legal/` | 许可说明 / licensing | Yes |
| `docs/release/`, `docs/store/` | 发布门、状态、可公开商店材料 / release gates, status and public store material | Yes |
| `docs/media/` | 合成数据的公开演示素材 / public demonstrations with synthetic data | Yes |
| `docs/privacy.*` | 保持稳定路径的隐私页面 / stable privacy-policy endpoints | Yes |
| `tools/`, `.github/` | 维护脚本、CI 和模板 / tooling, CI and templates | Yes |
| `.local/private/` | 产品/设计/研究/历史实验/诊断/备份 / product, design, research, experiments, diagnostics and backups | No |
| `.local/work/`, `.local/releases/` | 临时产物和发行压缩包 / temporary outputs and release ZIPs | No |
| `.trellis/`, `.agents/`, `.codex/` | 可选的本机开发工具 / optional local automation | No |
| `extension/dist/`, `node_modules/`, `coverage/` | 生成物 / generated output | No |

根目录仅放项目入口、许可证、贡献与治理文件和必要配置。新增文档按读者用途归类；文件名使用简短的英文 kebab-case，中文/英文版本使用明确语言后缀并互链。不要在目录名里混入任务编号、个人用户名或本机日期来代替分类。

Keep root files limited to project entrypoints, licensing, governance and essential configuration. Group documentation by reader purpose. Use concise English kebab-case filenames and explicit language suffixes for translations, with reciprocal links. Avoid task IDs, personal names or machine-local dates as directory categories.

私有归档保留原文件和迁移清单，不把“归档”目录放进公开 Git 来保存不能公开的材料。本机自动化目录保留原位以兼容进行中的会话。测试需要的样例必须合成并放进公共测试目录，不能读取维护者私有任务。生成清单 `extension/release-candidate.json` 随检查重新生成，不提交。

Private archives retain original files and a local path mapping. An archive committed to Git is still public. Local automation stays in place for ongoing sessions. Tests must use synthetic fixtures in public test directories. `extension/release-candidate.json` is regenerated by release checks and is not committed.

提交前运行 `python tools/check-repository.py` 与 `python tools/check-docs.py`。前者检查暂存路径与明显凭据标记，后者检查文档链接、公开文件边界、许可和素材；它们不是完整的秘密或历史审计。旧跟踪文件必须显式取消跟踪，`.gitignore` 本身不会清除 Git 历史。

Before committing, run the repository and documentation checks above. They validate staged paths, obvious credential markers, public links, licensing and assets; they are not comprehensive secret or history audits. Ignoring an already tracked file does not untrack it or remove old commits.
