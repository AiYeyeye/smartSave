智栏隐私政策

生效及更新日期：2026 年 10 月 23 日。适用于 Astraxine 维护的智栏 / Zhilan 浏览器扩展 0.1.0 当前候选版本。联系：mmgnosit@gmail.com。English。

我们如何处理信息

智栏帮助你管理浏览器原生书签，并按需查询浏览历史。无需智栏账号，当前没有智栏运营的后端、遥测、广告或分析服务。维护者不会自动接收你的书签、API Key 或调试日志。这不代表所有数据都只在本机：启用 AI 后，允许的信息会发送给你选择的模型服务；浏览器自身也可能同步书签和偏好。

本机保存什么

  • 读取书签标题、原始网址、收藏时间（如有）、目录层级和浏览器节点标识，用于显示、搜索、分类、导入导出和恢复。书签仍保存在浏览器里，智栏直接读取和管理它们。

  • 本地保存 AI 连接、模型分配、隐私选项、网站规则、收藏处理回执、生成的搜索关键词、整理任务/导入草稿，以及写入日志、备份和恢复记录。部分记录含标题和原始网址。

  • 勾选“记住密钥”会将 API Key 明文保存在扩展本地存储，不是系统密钥保险箱。添加连接的表单当前默认勾选记住。取消后，临时密钥仅在对应页面或任务内存中保留，关闭/刷新原页面或后台任务终止后可能丢失，不能作为跨页面会话密钥使用。

  • Token 统计在本地保存用量、模型和用途等信息，不保存 Key、提示词、服务地址或书签正文。当前保留累计统计、约 30 天的每日分组及最近 100 次请求记录；没有单独清空统计的按钮。

  • 调试日志默认关闭。开启后会在本地保留经过脱敏、截断的请求/响应细节，仍可能包含书签标题、网址和启用正文辅助时的正文片段。最多 400 条、约 1 MiB，单个正文最多 64 Ki 字符。可在“收藏记录与调试”关闭并清空日志。分享前仍应自行检查。

语言、明暗模式、主题色可通过浏览器 storage.sync 同步；模型密钥、服务地址、目录规则、书签关键词和恢复日志不通过此偏好同步功能发送。浏览器账号对原生书签的同步由浏览器自身设置控制。系统或浏览器配置备份可能另行复制本地数据。

新手步骤的待查看或已关闭状态仅保存在本机；查看步骤不会发送网页或书签给 AI。

可选历史查询

点击“启用历史查询”后才请求 history 权限；只查询当前浏览器向扩展提供的标题、网址、标识和访问时间，不删除历史，不采集网页正文，不监听每一次浏览活动。检索结果仅在当前页面内存中保留，关闭页面释放；浏览器删除历史或撤销权限会清空搜索缓存并使待返回的 AI 结果失效。主动打开的收藏草稿单独保留，确认保存后的书签和恢复日志遵循书签保留规则。可在历史区点击“关闭历史访问”撤销权限。

只有主动点击“AI 查历史”才会发起本次 AI 查询：先发送查询文本、当地日期及所选时间范围理解条件，再发送查询和最多 80 条候选的标题、去掉参数和片段的网址、访问时间。不会发送完整历史库；不会读取网页正文。与隐私排除目录中书签网址完全相同的历史项也不会进入排序请求。从历史收藏时，AI 分类需另行点击，并发送该条标题、去参数网址及允许的目录上下文。历史查询、排序和历史收藏分类不记录请求/响应正文诊断；仍记录无内容的用途、用量和状态统计。原始网址用于用户主动打开、复制或保存，不因模型投影而改写。

哪些信息可能发送给 AI

配置连接并启用对应功能后，请求直接发往你指定的服务地址，使用该服务所需的凭据。该服务及你配置的中转/网关会接收请求和连接元数据（例如 IP）。不同功能使用不同范围：

  • 新收藏自动归类： 新书签标题、允许发送的网址、目标目录信息及分类偏好。点星标或 Ctrl+D 创建书签后可能自动调用，不要求每次另点 AI 按钮；命中本地规则可跳过分类请求，但配置智能收藏模型后仍可能单独请求名称建议；名称建议需在收藏确认浮层中明确采用才写入。

  • 当前页收藏： 当前页标题、网址及允许的目录上下文。显式收藏的正文辅助默认关闭，仅在相关开关启用时按需提取并发送最多 1,500 个 Unicode 字符，不后台遍历网站。

  • AI 搜索： 普通搜索在本机完成。主动点击 AI 搜索后，较大且含多个目录的集合先发送查询、允许范围内目录的完整路径、书签数量及每目录最多 3 个截短标题样本，用于排序和生成短检索词；随后每批最多 100 条发送允许范围内书签的标题、网址、收藏时间（如有）、目录路径及原始查询。普通查询找到首批匹配后暂停，可明确继续发送剩余批次；要求全部或尚无匹配时继续检查。目录排序失败按本地顺序继续；最近收藏查询先在本地筛选近 90 天，完整检查后无确认匹配才补查到近 360 天；明确日期或手动时间范围不自动扩大。取消后不再发送后续批次，已发送信息无法撤回。明确的网站或唯一文件夹查询可在本地完成，不调用模型。隐私排除的书签不发送 AI，仍可本地搜索。搜索不读取网页正文。

  • AI 整理： 先分批发送所选允许范围内全部书签的标题、网址和原目录，再发送全部分析主题及数量用于生成分类，并分批核对书签去向。发现缺少类别时可修订一次分类并重新核对全部书签，相关元信息会再次发送。请求还包括允许的目录层级、目标目录及你的整理要求，不读取网页正文。主题分析、分类版本和待确认结果保存在本机整理任务中；旧任务可能继续使用少量标题样本的原流程。

  • 导入分类： 从文件解析出的书签标题/网址、来源路径/样本和目标目录上下文，不抓取导入网址的网页。

  • 模型列表及连接测试： 列表请求使用服务凭据；连接测试发送合成测试内容。连接测试不使用当前网页。

“发送完整网址（含查询参数和片段）”当前默认开启，参数可能包含私人信息。关闭后只清理发往 AI 的对应网址字段，不改写书签、导出或备份中的原始网址。排除目录及其子目录不会进入 AI 上下文；内网/回环网址不自动视作私密，请按需排除。AI 排除范围与手动导出范围分别设置。模型输出作为数据校验，不能执行远程代码；批量书签写入仍需预览确认。

所选服务可能在不同国家/地区处理和保留数据。其留存、训练用途、分包商和删除机制由该服务的条款决定；智栏无法替其保证或删除已发送数据。请先查阅实际服务商或自建网关的隐私政策。选择本地模型不会自动回退到云服务。

其他连接与权限

可选书签检查

“书签检查”的重复比较在本机完成，不使用 AI。主动点击检查、继续检查或启用每周检查时会请求 HTTP(S) 网站访问权限；启用周检后，即使设置页关闭，浏览器运行时也会连接所选范围内的书签网站。请求使用原始路径和查询参数（不含片段），目标网站可看到网址及连接元数据，例如 IP。此功能独立于 AI 的网址脱敏设置；可以选择文件夹来限定检查范围。

检查先发送 HEAD，必要时用 GET 核对响应状态。异常页面还会检查同一主机的网站入口；连接失败时通过 HTTP 和 HTTPS 各复查，入口请求不含原收藏路径、查询参数或片段，自定义端口保持不变。同一检查内复用网站响应证据。不读取网页正文，不携带浏览器 Cookie 或来源页信息，不自动跟随跳转。非网页、带账号密码和可识别的本机/内网地址会跳过；域名解析和网站行为仍由网络环境及目标网站决定。检查结果、原生书签标识、原始网址、进度和周检设置仅保存在扩展本地数据库，不同步、不发送模型，也不写入调试日志。新检查替换旧报告，范围切换清除旧报告；关闭周检不清除报告。撤销网站访问权限会暂停正在进行的检查，取消周检可停止后续自动检查。检查不会自动删除收藏。alarms 权限仅用于调度已启用的每周检查。

可选的 OpenRouter 登录会在你主动操作后请求 identity 和对应主机权限，打开 OpenRouter 登录/授权页，并通过授权码与 PKCE 交换 API 凭据。账号密码由该服务处理，智栏不读取。第三方条款见 OpenRouter 隐私政策。

书签图标通过浏览器自己的 favicon API 读取，没有接入第三方图标网站；浏览器如何获取/缓存图标由浏览器决定。主动打开书签后，目标网站按其政策处理访问。使用 GitHub 反馈或邮箱联系时，你主动提供的信息会交给对应平台及维护者处理，用于回复和解决问题。

bookmarks 用于书签管理；storage 用于本地数据及上述偏好同步；activeTab/scripting 用于用户触发的当前页读取和侧栏注入；contextMenus 提供收藏菜单；favicon 显示图标；sidePanel 提供浏览器侧边栏。可选 identity 用于上述登录，history 用于用户启用的历史查询；可选 HTTP(S) 主机权限按实际模型地址或主动启用的书签检查授权，不在安装时授予全部网站访问。只有侧栏文档被声明为网页可访问资源；没有常驻的 manifest 内容脚本。

保留、导出与删除

收藏回执通常保留最近 30 条，尚待确认的名称建议另外保留；关键词、任务、设置及恢复记录按各自容量和状态保存在本机，不承诺统一自动到期。恢复清理会保留必要的去重证据，并可能拒绝清理结果未知或被引用的记录。导入草稿、用量统计等目前没有完整的一键清理功能。

你可停用 AI、撤销对应站点权限、删除连接和清理调试日志。连接存储和兼容配置中可能分别保留密钥：删除连接或某一处密钥不能保证清除所有副本。 如需完全撤销凭据，请到服务商处撤销；如需清除扩展本地数据，先完成未知操作核对、备份所需信息、停止自动输出，再按浏览器方式清除扩展数据或卸载。卸载会丢失本地恢复能力，但不会由智栏主动删除浏览器原生书签或已导出的文件。

手动书签导出含所选标题、目录和原始网址，不含模型配置、密钥、规则或日志；公开 AI 配置导出不含密钥，但可含服务地址和模型分配。自动 JSON 输出仅写入你选择并授权的专用文件，后续更新会覆盖内容；停止或卸载不会删除外部文件。已导出文件、浏览器同步副本和模型服务已接收的数据需分别管理。

数据用途承诺与政策更新

智栏仅为所披露的书签管理、历史查询、用户选择的 AI 辅助及必要运行使用数据，不出售用户数据，不用于广告、信用评估或无关用途；维护者不自动读取用户内容。智栏对通过 Google API 获得信息的使用和转移遵守 Chrome Web Store 用户数据政策，包括 Limited Use 限制。

本政策将随功能或数据流变化更新，并标明更新日期；新增需要同意的处理应在产品内提示。隐私问题、你主动提供的支持信息的查阅/删除请求，请联系 Astraxine：mmgnosit@gmail.com。本政策无法替你选择的第三方服务执行删除。

个性化偏好

“个性化偏好”在本机保存明确选择、反馈及规则；证据包括原生标识、标题、原始网址及相关目录，用于有效性与隐私检查。数据不通过浏览器偏好同步上传，也不加入书签导出。在智栏中手动改目录、修改 AI 建议的书签名，以及在整理页选择目录、确认归类或提交重分类反馈，都会记录。Chrome/Edge 原生书签管理器中的改目录和改名也会记录；浏览器事件不提供来源标识，其他扩展或同步造成的同类变化也可能进入记录。智栏自身的自动分类、整理、恢复写入和同目录内调序不会重复学习。直接采用 AI 名称不算人工改名；整理页明确确认归类则会记住。

偏好正文总计最多 3000 字、10 条（含条目间换行，按 Unicode 字符计数）。原始操作先留在本地学习队列，后台使用整理模型总结分类依据或命名习惯，成功后才保存为偏好，并与现有有效偏好合并、去重，保留最新要求。例如，明确反馈“API 教程放学习资料，不放工具”应总结为“这类教程按学习参考用途归类”，而不是重复移动记录。单次选择只支持较窄的判断；原因不明确时不编造用途或用户动机。设置中可以修改、停用、删除和添加内容，手动添加或编辑超限时也会整体压缩。失败保留原有偏好且不回滚书签，失败输入留在本地任务记录中，不自动重发。旧版超量记录会保留本地迁移副本，只有已启用且有效的内容参加更新。

后续书签搜索、整理、改名、收藏和导入分类按适用功能参考有效已启用的偏好，当前要求优先。整理审核记录意图，统一确认前不移动书签。已失效或隐私排除的证据、停用和待确认的规则不发送；历史查询和合成连接测试不使用偏好。关闭、修改或删除影响后续请求，无法撤回已发送的信息。 关闭完整网址时，含查询/片段分隔符的偏好文本也不发送。原始证据网址不会作为偏好正文发送。更新按每批最多 20 个新示例处理，并附上现有有效偏好；任务队列最多保存 5,000 个动作，完成或跳过后清除输入副本。运行中断标为失败且不自动重放，未发送任务可继续。已启用的调试日志可能包含偏好文本，删除偏好不会清理旧日志。

Zhilan Privacy Policy

Effective and updated: October 23, 2026. Applies to the current Zhilan 0.1.0 candidate maintained by Astraxine. Contact: mmgnosit@gmail.com. 简体中文.

Overview

Zhilan manages native browser bookmarks and optionally searches browsing history. It requires no Zhilan account and currently operates no product backend, telemetry, advertising or analytics service. The maintainer does not automatically receive your bookmarks, keys or diagnostic logs. Enabling AI sends permitted information to your chosen endpoint; the browser may independently synchronize bookmarks and preferences.

Local data and synchronization

The extension reads bookmark titles, original URLs, recorded save dates, folder hierarchy and native identifiers. Local extension storage and IndexedDB contain model connections, feature assignments, privacy choices, website rules, recent save receipts, generated search keywords, organization/import checkpoints, mutation evidence, backups and recovery records. Some contain original titles and URLs.

Remembered API keys are stored in plaintext extension-local storage, not an operating-system vault. The new-connection dialog currently selects remember by default. Unremembered credentials are held in the owning page or task's memory; closing/reloading the page or ending the worker/task can discard them. They are not a shared browser-session key.

Local Token accounting stores usage, model and purpose metadata, without keys, prompts, endpoints or bookmark content. It retains lifetime totals, approximately 30 days of daily groups and the latest 100 attempts; it currently has no individual clear control. Save receipts normally retain the latest 30 entries, with unresolved name suggestions kept separately. Other records follow their individual capacity and state rules, with no universal automatic expiry.

Debug logging is off by default. If enabled, bounded, redacted request/response details remain local and can still contain bookmark metadata and optional page snippets. Limits are 400 entries, approximately 1 MiB overall and 64 Ki characters per body. Disable and clear them in Save history & debug. Inspect any diagnostic export before sharing it.

Only language, appearance mode and accent synchronize through browser storage.sync. Keys, endpoints, rules, bookmark keywords and recovery records do not use that preference-sync feature. Native bookmark synchronization is controlled by your browser account. Browser/profile or system backups may separately copy local data.

The pending or dismissed state of Getting started is stored locally. Viewing the steps does not send pages or bookmarks to AI.

Optional history search

The history permission is requested only when you click Enable history search. It reads titles, URLs, identifiers and visit times exposed by this browser, without deleting history, reading page bodies or monitoring every navigation. Results stay in the current page memory and are released when it closes. Browser history deletion or permission revocation clears the search cache and invalidates pending AI results. Explicitly opened bookmark drafts remain separate; confirmed bookmarks and recovery evidence follow bookmark retention rules. Turn off history access revokes the permission.

AI history search starts only when you explicitly click AI history search for that query. Interpretation sends your query, local calendar date and selected date range; ranking sends the query and up to 80 candidates’ titles, URLs without query strings/fragments, and visit times. It does not send a full history database or read page bodies. History URLs exactly matching bookmarks in privacy-excluded folders cannot enter ranking. Optional classification when bookmarking a history result requires another click and sends that title, sanitized URL and permitted folder context. History interpretation, ranking and history-save classification do not record request/response body diagnostics; content-free purpose, usage and status accounting remains. Opening, copying and saving use the original URL.

AI requests

Requests go directly to your configured provider or gateway, including the required authentication. That service receives the request and connection metadata such as your IP address.

  • Native-save classification can run automatically after a browser-star/Ctrl+D save when configured. It sends allowed title/URL, folder context and preferences unless a local rule avoids classification. A configured save model may still receive a separate name-advice request after a local rule. Names change only after explicit adoption in the bookmark confirmation popup.

  • Explicit current-page capture uses permitted title/URL and folder context. Optional page-body assistance is off by default and, when enabled for an active save, extracts at most 1,500 Unicode characters. There is no background crawling.

  • Ordinary search stays local. For larger collections spanning multiple folders, explicit AI search first sends the query, permitted folder paths, scoped bookmark counts and up to three shortened title samples per folder for prioritization and short retrieval terms. It then sends permitted bookmark titles, URLs, recorded save dates, folder paths and the original query in batches of up to 100. Ordinary queries pause after initial matches; explicit continuation sends remaining batches. All-match requests and searches without confirmed matches continue scanning. Folder-planning failures fall back to local order. Recent-collection searches filter the last 90 days locally first; a completed phase with no confirmed match expands to 360 days without resending checked items. Explicit dates and manual time ranges do not expand automatically. Cancellation stops later batches but cannot recall information already sent. Clear website or uniquely named folder queries can complete locally without model calls. Privacy-excluded bookmarks remain locally searchable and are never sent to AI. Search does not read page bodies.

  • Organization first sends every permitted bookmark's title, URL and original path in batches, then all analyzed topics/counts to draft categories, followed by batches to check destinations. Missing categories can trigger one revision and another assignment pass, sending the relevant metadata again. Requests include permitted folder hierarchy, destinations and your instructions, without fetching page bodies. Topic analysis, taxonomy versions and uncertain results are saved in local tasks. Older saved tasks may retain the previous title-sampling workflow. Import classification sends parsed titles/URLs, bounded source paths/samples and destination context, without fetching imported websites.

  • Model discovery authenticates to the configured endpoint. Connection tests use synthetic content, not the current webpage.

Full URL transmission, including query strings and fragments, currently defaults on. Disabling it strips these components only from AI URL fields; native bookmarks, exports and backups retain originals. Excluded folders and descendants are removed from AI context. Internal/loopback bookmark addresses are not automatically excluded. Export scope is independent of AI exclusions.

Provider retention, training, subprocessors, processing locations and deletion depend on the chosen service's terms. Zhilan cannot guarantee their practices or erase information already sent. Review the actual provider/gateway policy first. Local-model mode does not automatically fall back to the cloud. Model responses are validated data, not executable remote code; bulk native writes require preview and confirmation.

Other connections and permissions

Optional bookmark checks

Duplicate comparison runs locally without AI. Starting/resuming a link check or enabling weekly checks requests HTTP(S) website access. Once enabled, weekly checks contact bookmarked websites in the selected scope while the browser runs, including when settings are closed. Requests use the original path and query parameters, without fragments; destination websites receive the URL and connection metadata such as your IP. This is separate from AI URL redaction settings. Choose a folder to limit the scope.

Checks send HEAD and, when needed, GET to verify response status. For page issues they also check the same host’s website entry, repeating failed connections over HTTP and HTTPS; entry requests omit the original path, query and fragment and preserve custom ports. Website response evidence is reused within the scan. Checks do not read page text, send browser cookies or referrer information, or automatically follow redirects. Non-web, credential-bearing and recognizable local/private addresses are skipped; DNS resolution and website behavior still depend on the network and destination. Results, native bookmark IDs, original URLs, progress and weekly settings stay in a local extension database. They are not synced, sent to models or written to debug logs. A new scan replaces the report; changing scope clears it. Disabling weekly checks retains the report. Revoking website access pauses active checks; disabling weekly checks stops future scheduled checks. Checking never automatically deletes bookmarks. The alarms permission schedules only opted-in weekly checks.

Optional, user-initiated OpenRouter sign-in requests identity and its host permission, opens the provider's authorization page and exchanges a code/PKCE verifier for API credentials. Zhilan does not receive your account password. See OpenRouter privacy.

Favicons use the browser-owned favicon API, with no extension-integrated third-party icon service; the browser controls its own retrieval/cache. Opening a bookmark visits the destination under its policy. If you contact support by GitHub or email, the platform and maintainer process what you choose to send for support.

Required permissions support bookmarks, local settings/preferences, user-triggered current-tab extraction/overlay injection, context menus, favicons and the native side panel. Optional identity supports sign-in; optional history supports user-enabled history search; optional HTTP(S) host access is requested for specific model hosts or user-enabled bookmark checks. Installation does not grant all-site access. The overlay document is web-accessible; there are no persistent manifest content scripts.

Control, retention and deletion

You may disable AI, revoke host access, remove connections and clear diagnostics. Credentials can exist in both connection storage and a compatibility envelope: deleting one connection/key does not guarantee all local copies are removed. Revoke credentials at the provider to invalidate them completely.

There is currently no universal in-app data eraser. Recovery cleanup preserves required deduplication evidence and refuses some unresolved/referenced records. To remove all local extension data, first reconcile unknown operations, preserve needed information and stop automatic output, then use browser extension-data controls or uninstall. This loses local recovery capability. Zhilan does not intentionally delete native bookmarks or external exports on uninstall.

Bookmark exports contain selected titles, hierarchy and original URLs, without keys/settings/rules/logs; they are not complete recovery backups. Public AI configuration exports omit credentials but can include endpoints and model assignments. Automatic JSON output overwrites only a dedicated user-selected authorized file. Stopping/uninstalling does not remove it. Manage exported files, synchronized copies and provider-held data separately.

Limited Use and updates

Zhilan uses data only for disclosed bookmark management, history search, user-chosen AI assistance and necessary operations. It does not sell user data or use it for advertising, creditworthiness or unrelated purposes. The maintainer does not automatically read user content. The use and transfer of information received from Google APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements.

We update this policy when behavior changes and show the update date. New processing requiring consent should be disclosed in the product. Contact Astraxine at mmgnosit@gmail.com for privacy questions or access/deletion requests relating to support information you provided. We cannot delete data held by your chosen provider on your behalf.

Personal preferences

Personal preferences stores explicit choices, feedback and rules locally. Evidence contains native IDs, titles, original URLs and relevant folders for freshness and privacy checks. These records are not included in preference sync or bookmark exports. Zhilan records manual folder changes, edits to AI-proposed bookmark names, and organizer destination selections, explicit classification approvals and reclassification feedback. Native Chrome/Edge bookmark-manager moves and renames are also recorded. Browser events do not identify their source, so equivalent changes from sync or other extensions may also be recorded. Zhilan suppresses its own classification, organization and recovery writes and reorder-only events. Unchanged adoption of an AI name is not a correction; explicit organizer classification approval is remembered.

Preference text is limited to 3000 Unicode characters and 10 entries in total, including newlines between entries. Raw actions stay in the local learning queue. The organize model summarizes supported classification criteria or naming habits; only a successful summary becomes a preference and merges with the usable profile, removing duplication and giving newer choices priority. For example, explicit feedback to file API tutorials under Learning rather than Tools supports treating those tutorials as learning references, rather than repeating the move. A single choice supports only a narrow interpretation; unclear reasons must not become invented purposes or private motives. Edit, disable, delete or add content in settings; oversized manual additions or edits also trigger whole-profile compression. Failure retains the existing profile and never rolls back bookmarks; failed input remains in local job records without automatic retry. Oversized legacy records retain a local migration copy; only enabled, valid content participates in updates.

Subsequent bookmark search, organize, rename, save and import-classification requests use applicable enabled preferences, with current instructions taking priority. Organizer review records intent; native bookmarks move only after final confirmation. Stale or privacy-excluded evidence, disabled entries and pending rules are withheld. History and synthetic connection tests do not use preferences. Changes affect subsequent requests and cannot recall previously sent data. With full URLs disabled, text containing query/fragment separators is withheld. Raw evidence URLs are not sent as preference text. Updates use at most 20 new examples per batch plus the existing usable profile. The local queue retains at most 5,000 action records and clears input copies after completion or skipping. Interrupted calls fail without automatic replay; unsent work may continue. Opt-in diagnostics can contain preference text; deleting preferences does not clear earlier logs.
